# ADR-0003 — decision recorded under "Proof of a live session comes from the caller"

- Contract owner: [session-contract.md](../session-contract.md#why-the-tool-must-not-guess-whether-you-are-signed-in)

## Decision record

- 목적과 의도: 만료된 세션이 성공으로 보고되는 것을 막되, 도구가 인증 여부를 추측하지는 않게 한다.
- 기존 구현 및 제약 조건: `policy.js`는 캡차·하드 블록·로그인 경로 리다이렉트처럼 모호하지 않은 형태만 잡는다. 인증 여부를 판정할 옵션은 없고, 로그인 페이지도 렌더된 페이지이므로 검증을 통과한다.
- 검토한 주요 대안: 범용 휴리스틱으로 로그인 여부를 감지한다, 대상별 감지 규칙을 도구에 내장한다, 호출자가 증거 문자열을 넘긴다.
- 선택한 방식: 호출자가 대상별로 "로그인되어 있다"를 증명하는 마커를 제공하고, 마커가 없으면 항목을 실패가 아니라 사람이 개입할 수 있는 상태로 올린다.
- 다른 대안 대신 이 방식을 선택한 이유: 휴리스틱을 실제로 재봤고 양방향으로 틀렸다. JSON API 응답에는 로그인 UI가 없어 거짓 경보가 나고, 로그아웃된 포털 페이지에는 로그인이라는 단어조차 없어 거짓 통과가 난다. 거짓 통과는 이 계층이 막으려는 실패 그 자체다. 대상별 규칙을 내장하는 쪽은 사이트가 바뀔 때마다 도구가 틀리고, 틀렸다는 사실이 사용자에게 보이지 않는다.
- 장점, 단점 및 영향: 판정이 그것을 아는 쪽으로 옮겨가고, 도구는 추측한 적이 없으므로 조용히 틀리지 않는다. 대신 마커를 넘기지 않은 호출은 예전과 똑같이 동작하므로, 이 결정은 문서가 마커를 안내할 때만 값이 생긴다. 도구와 문서를 같이 내보내야 하는 이유가 이것이다.
