# ADR-0002 — decision recorded under "The block carries criteria, the skill carries procedure"

- Contract owner: [install-surface.md](../install-surface.md#the-division-of-labour-between-the-two-documents)

## Decision record

- 목적과 의도: 설치기가 쓰는 두 문서의 역할 경계를 확정한다. 무엇이 상시 주입 구간에 들어가고 무엇이 온디맨드 스킬로 가는지.
- 기존 구현 및 제약 조건: 경계는 사실상 이미 그렇게 구현돼 있었지만 근거가 기록된 적이 없어, 새 문장이 생길 때마다 어디에 넣을지를 매번 다시 논쟁해야 했다.
- 검토한 주요 대안: 구간을 자족적으로 만들어 스킬 없이도 동작하게 한다, 반대로 구간을 포인터만 남기고 최소화한다, 현행 분담을 근거와 함께 고정한다.
- 선택한 방식: 구간은 판단 기준만 — 언제 배치하고 언제 네이티브로 남는지, 상태어가 무엇을 뜻하는지, 무엇을 하면 안 되는지. 절차·실패 코드·재개 방법은 스킬이 소유한다.
- 다른 대안 대신 이 방식을 선택한 이유: 호스트 자신이 그렇게 동작한다. Aside는 자기 스킬들의 라우팅 메타데이터만 매 턴 주입하고 본문은 필요할 때 읽으며, 자기 에이전트에게도 워크플로에 필요한 만큼만 읽으라고 지시한다. 호스트의 설계를 따르는 쪽이 우리가 다른 규칙을 발명하는 쪽보다 낫다.
- 장점, 단점 및 영향: 새 문장의 소속을 판정하는 기준이 생기고, 상시 비용이 판단에 필요한 만큼으로 유지된다. 대신 구간만 읽은 에이전트는 절차를 모르므로, 구간은 스킬 경로를 항상 명시해야 한다.
