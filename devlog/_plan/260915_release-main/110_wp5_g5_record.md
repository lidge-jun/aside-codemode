# 110 — wp5 결과: G5의 경계와 면제

G5는 **돌리지 않았다.** 통과로 세지 않는다.

게이트 원문은 "새 에이전트 세션, 경로 선택 평가, cold/warm 비교"이고 합격선은 "정답 유지,
native 단일 작업에 불필요한 우회가 없음"이다. 그 본체는 모델이 native와 배치 중 하나를
고르게 하고, native가 맞는 요청을 절반 이상 섞어 **적절히 안 불렀는지**까지 채점하는
일이다. 그런 세션은 이 저장소에 없다.

## 있는 것과 없는 것

| | |
|---|---|
| 있음 | 480실행 (워크로드 4종 x cold/warm x 30쌍, 오류율 0). **R6의 성능·정답 자료**다 |
| 있음 | first-look의 정답 30/30, 왕복 3콜 대 1콜, 복구 중앙값 6~7ms. 경로가 **고정된** 실행이다 |
| 있음 | 설치된 스킬과 AGENTS 블록에 native-first 안내가 실려 있다 (문서·설치 회귀로 검사) |
| 없음 | 모델이 경로를 고른 새 세션. 그 선택의 정답률과 불필요한 우회 여부 |

480실행의 하니스는 경로를 스스로 고르지 않는다. `eval/workloads/*.json`의 각 path는 어떤
프로그램을 돌릴지 미리 적혀 있다. 그래서 그 숫자는 "고정된 경로에서 얼마나 빠르고
정확한가"이지 "경로를 잘 골랐는가"가 아니다. 설치 문서에 native-first 문장이 있는지 보는
검사도 마찬가지다 — 안내가 남아 있는지를 볼 뿐 모델이 그걸 따랐는지는 모른다. 그 검사를
G5나 경로 선택 평가라고 부르지 않는 이유이고, 파일 이름도 `docs-guidance`다.

## 면제

앞 루프의 090은 G0~G5 통과를 RC 조건으로 뒀고, 100_rc_record.md는 G5 미실행 때문에
NEEDS_HUMAN으로 멈췄다. 게이트의 주인은 사용자다.

    누가    사용자
    언제    2026-09-15
    무엇을  세 기기(mac, ssh mini, macmini-cf) 배포와 main 릴리즈까지 진행하라는 지시

이 지시로 G5 미실행은 main 승격의 막대에서 빠진다. **이것은 출시 기준의 변경이지 게이트
통과가 아니다.** 그래서 이 릴리즈는 R6를 닫았다고 쓰지 않는다 — 원문 R6의 완료 증거가
G0~G5 receipt이기 때문이다.

## 릴리즈 노트에 실을 문단

> 이 릴리즈는 G5(사용성·경로 선택)를 실행하지 않았고 통과로 세지 않는다. 새 에이전트
> 세션에서 모델이 native와 배치 중 하나를 고르고, native가 맞는 요청을 절반 이상 섞어
> 정답 유지와 불필요한 우회 없음을 채점하는 평가는 없다. 함께 공개하는 480실행은
> 스크립트가 경로를 고정한 성능·정답 자료이며, 설치된 스킬이 첫 탐색과 단일 클릭을
> native로 남기라고 적고 있는지는 안내 문서의 내용일 뿐 경로 선택의 증거가 아니다.
> 2026-09-15 사용자 지시로 G5 미실행은 main 승격의 blocker에서 빠졌고, 이는 출시 기준의
> 변경이지 게이트 통과가 아니다.
