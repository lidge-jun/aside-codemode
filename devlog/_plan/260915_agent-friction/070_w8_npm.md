# 070 — w8: npm 배포 가능 여부 (감사 반영본)

판정만 하고 publish는 하지 않는다.

1. **이름.** aside-codemode가 레지스트리에 비어 있는지 확인한다.
2. **무엇이 들어가는지.** npm pack --dry-run의 실제 목록을 본다. 금지 목록만 보지 말고
   **들어가는 것 전부**를 읽는다. 지금 files는 bin/과 scripts/를 통째로 넣는데, 거기엔
   추적된 Windows 바이너리 bin/rg.exe(4MB)와 probe-g3·rehearse-install·release-records·
   backup-accounts 같은 개발용 스크립트가 있다. 그것들이 패키지에 있어야 하는지 판단하고
   적는다.
3. **실행 진입점.** bin.codemode → bin/codemode.mjs, shebang, engines.node(>=18, CI 18/20/22).
4. **저장소 밖에서 템플릿을 찾는가.** doctor는 템플릿을 열지 않으므로 그것으로는 증명되지
   않는다. tarball을 임시 디렉터리에 풀고 **plannedFiles()와 install --dry-run**을 그 안에서
   돌려야 REPO_ROOT 기준 템플릿 해석이 증명된다.

판정은 셋 중 하나: 지금 가능 / 준비하면 가능(무엇을) / 불가능(왜).

## 판정 (실측, 2026-09-15)

**지금 가능하다.** 아래 다섯 가지를 고친 뒤의 이야기이고, 그 다섯 가지는 이 work-phase에서
같이 고쳤다. 고치기 전 상태로는 이름도 비어 있고 설치도 되지만, 남의 바이너리를 고지 없이
재배포하는 문제가 남아 있었다.

**이름.** `npm view aside-codemode`가 E404. 레지스트리에 비어 있다.

**리포 밖에서 도는가.** tarball을 /tmp에 풀고 그 안에서 `node bin/codemode.mjs --doctor`,
실제 `search.files`, `plannedFiles()`, `install --dry-run`을 돌렸다. 여섯 파일 전부
(call-shapes.md 포함) 계획되고, 템플릿은 REPO_ROOT 기준으로 정상 해석된다. `npm i -g`로
임시 prefix에 깔아 `codemode --doctor`가 ok:true를 반환하는 것까지 확인했다. doctor만으로는
템플릿 해석이 증명되지 않기 때문에 installer를 직접 돌린 것이다.

**고친 것 다섯.**

1. `bin/THIRD-PARTY-NOTICES.md` — ripgrep MIT 전문과 PCRE2 고지를 바이너리 옆에 싣고
   패키지에 넣었다. MIT는 재배포 사본에 저작권 고지와 허가 문구를 포함할 것을 요구하는데,
   bin/README.md의 링크는 고지가 아니다. 우리 LICENSE는 우리 것만 덮는다. 감사가 바이너리
   strings에서 Andrew Gallant와 pcre2를 확인했고, Windows 빌드가 PCRE2를 링크하므로 BSD
   고지도 함께 넣었다. 이것 하나가 유일한 실제 차단 사유였다.
2. `files[]`에서 `scripts/` 통째 포함을 뺐다. probe-g3와 probe-native-helper는 기본값이
   `~/.aside/u/0`라 살아 있는 계정에 헬퍼를 쓰고, release-records는 evidence/와 git을 리포
   cwd에서 돌린다. src/도 bin/도 이 스크립트들을 임포트하지 않는다. 남긴 것은 install-codemode,
   register-aside 3종, run-tests뿐이다. 77 entries, 1.95MB.
3. `npm test`가 설치본에서 ENOENT로 죽던 것을 고쳤다. test/는 체크아웃에만 있으므로
   run-tests가 그렇게 말하고 0으로 끝난다.
4. repository / homepage / bugs / keywords / author를 넣었다. 없어도 게시는 되지만
   레지스트리 페이지가 비어 보인다.
5. `src/rg.js`의 후보 사다리 맨 끝에 Windows 한정으로 패키지 안의 `bin/rg.exe`를 넣었다.
   감사가 짚은 구멍이다 — rgPath는 register가 써 주는데 npm으로 받은 사용자에게는 register
   단계가 없어서, 우리가 실어 보낸 바로 그 바이너리만 PATH가 못 찾고 있었다.

**남기는 판단.** rg.exe는 계속 싣는다. 4.2MB로 unpacked의 88%지만 압축 후 약 1.7MB이고,
PATH에 rg가 없는 Windows에서 이 패키지가 돌아가는 유일한 이유다. macOS/Linux 사용자는
그 용량만 받고 기능은 영향이 없다 — 해석 사다리가 비Windows에서 .exe를 무시한다.

**publish 자체는 이 릴리스에서 하지 않는다.** 판정과 준비까지가 이 work-phase의 범위다.
